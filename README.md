# training_diary — щоденник тренувань

Наскрізний проєкт з дисципліни «Програмування мовою Dart», варіант 7
«Щоденник тренувань».

Автор: Зьома Гліб Ярославович, група ПЗПІ-23-10.

## Лабораторна робота 1. Функції та обробка колекцій

Консольна програма розбирає вбудований набір записів щоденника, відкидає
пошкоджені рядки з поясненням причини, перевіряє діапазони значень і формує
текстовий звіт: хронологію, топ за дистанцією, темп, групування за видами
активності й підсумкові значення. Класи навмисно не використовуються.

### Запуск

```bash
dart pub get
dart run
dart analyze
dart test
```

### Формат вхідних даних

Один рядок — одне тренування, поля розділені `;`:

```
дата;вид активності;тривалість;дистанція, км;пульс;самопочуття;ID трекера
2026-09-02;біг;0:42;7.1;152;4;GRM-4821-7731
```

| Поле | Формат | Перевірка під час розбору | Перевірка валідатором |
|---|---|---|---|
| дата | `yyyy-MM-dd` | регулярний вираз + `DateTime.tryParse` + захист від нормалізації | не раніше 2000 р., не в майбутньому |
| вид активності | текст | непорожній | — |
| тривалість | `г:хх` | регулярний вираз з іменованими групами | > 0 і ≤ 12 год |
| дистанція | дробове число | `double.tryParse` | 0…300 км |
| пульс | ціле число | `int.tryParse` | 40…220 уд/хв |
| самопочуття | ціле число | `int.tryParse` | 1…5 |
| ID трекера | `ABC-1234-5678` | регулярний вираз з іменованими групами | — |

Поле «ID трекера» додано до сутності варіанта, щоб мати змістовне значення
для маскування через `replaceAllMapped`.

Набір даних містить 25 рядків: 16 повністю коректних, 7 пошкоджених на етапі
розбору (відсутнє поле, нечислова дистанція, нечисловий пульс, неіснуючі дати
`2026-02-30` і `2026-13-01`, тривалість `45хв`, невірний ID трекера) та 2, що
розбираються, але не проходять валідацію.

## Обґрунтування прийнятих рішень

### Структура програми та розподіл між `bin/` і `lib/`

`bin/training_diary.dart` містить лише точку входу: виклик функцій і вивід
результату. Уся логіка лежить у `lib/`, щоб її можна було тестувати й
повторно використати в ЛР 2–4:

| Файл | Призначення |
|---|---|
| `lib/workout.dart` | `typedef` для запису тренування, результату розбору, порівнювача й предиката |
| `lib/constants.dart` | усі іменовані константи (формат, межі, ширина колонок) |
| `lib/data.dart` | константний список вхідних рядків |
| `lib/parsing.dart` | розбір рядків, регулярні вирази, лічильник-замикання, маскування |
| `lib/validation.dart` | перевірка діапазонів, розділення на коректні/некоректні |
| `lib/analytics.dart` | конвеєри, групування, сортування, фабрики предикатів, арифметика дат |
| `lib/report.dart` | форматування звіту через `StringBuffer` |
| `lib/training_diary.dart` | бібліотека-агрегатор (`export`) для `bin/` і `test/` |

### Вибір типів даних

- **Тренування — іменований запис** `({DateTime date, String activity, ...})`,
  оголошений через `typedef Workout`. Класи в ЛР 1 заборонені, а запис дає
  статичну типізацію полів, незмінність і структурну рівність без класу.
  `typedef` прибирає повторення довгого типу в кожній сигнатурі.
- **Тривалість — `Duration`**, а не кількість хвилин `int`: її можна
  додавати (`fold(Duration.zero, ...)`), порівнювати й отримувати
  `inHours`/`inMinutes` без ручної арифметики.
- **Дистанція — `double`** (дробові кілометри), **пульс і самопочуття — `int`**.
- **Результат розбору — запис `({Workout? value, String? error})`**, а не
  просто `Workout?`: так програма повідомляє, *чому* рядок відхилено.
  Виняток у `try/catch` не використовується, бо пошкоджений рядок — очікувана
  ситуація, а не виняткова.
- **Групи — `Map<String, List<Workout>>`** з ключем «вид активності».
- **Порушення валідації — `List<String>`**: порожній список означає, що
  запис коректний; список будується через collection-`if`.

### Ключові рішення в реалізації

- **Захист від нормалізації дат.** `DateTime.tryParse('2026-02-30')`
  повертає `2026-03-02`, а `'2026-13-01'` — `2027-01-01`. Тому `parseDate`
  після розбору порівнює місяць і день з тими, що записано в рядку, і
  відкидає такі дати.
- **Розбір через list pattern** `if (parts case [final rawDate, ...])`
  замість звертання за індексами `parts[0]`, `parts[1]`: немає магічних
  індексів, а перевірка кількості полів відбувається автоматично.
- **Агрегація** — конвеєри `where → map → fold`. `longestWorkout`
  використовує `fold<Workout?>(null, ...)`, а не `reduce`, бо `reduce` кидає
  `StateError` на порожній колекції.
- **Пошук** — `where(...).firstOrNull` з `dart:core`.
- **Сортування** — `sortWorkouts(items, by:, thenBy:, ascending:)` повертає
  копію (`[...items]..sort(...)`), не змінюючи вхідний список. Критерії
  передаються як функції-порівнювачі.
- **Замикання.** `makeCounter()` повертає функцію, яка захоплює локальну
  змінну `count`; вона нумерує рядки під час розбору. `byActivity(activity)`
  і `minDistance(km)` — фабрики предикатів, що захоплюють свій параметр.
- **Регулярні вирази** записано сирими рядками `r'...'` з іменованими
  групами (`year`, `month`, `day`, `hours`, `minutes`, `vendor`, `serial`,
  `tail`). Маскування `GRM-4821-7731 → GRM-****-7731` виконує
  `replaceAllMapped`.
- **Дата «сьогодні»** передається параметром `DateTime? today` і
  підставляється як `today ?? DateTime.now()`, оскільки `DateTime.now()` не
  є константою й не може бути значенням за замовчуванням. Це також робить
  тести детермінованими.
- **Звіт** формується `StringBuffer` з каскадами `..writeln`, а не
  конкатенацією `+=`.

### Оператор `!`, `late`, `dynamic`

У коді **не використовуються** ні оператор `!`, ні `late`, ні `dynamic`.
Nullable-значення обробляються через перевірку на `null` з промоцією типу
локальних змінних, `??` та `.nonNulls`. У колбеку `replaceAllMapped`, де
приходить базовий тип `Match`, застосовано перевірку `match is RegExpMatch`
(промоція типу) замість приведення `as`.

### Залежності

Залежностей часу виконання немає — завдання виконано засобами `dart:core`.

| Залежність | Тип | Навіщо | Альтернатива |
|---|---|---|---|
| `lints` | dev | набір правил `recommended` для `dart analyze` (вимога дисципліни) | `package:flutter_lints` — для Flutter, не підходить; `very_good_analysis` — зайва стороння залежність |
| `test` | dev | модульні тести логіки розбору та агрегації | офіційний пакет команди Dart, альтернатив у стандартній бібліотеці немає |

### Налаштування аналізатора

`analysis_options.yaml` підключає `package:lints/recommended.yaml` і посилює
його: `strict-casts`, `strict-inference`, `strict-raw-types`, а також правила
`public_member_api_docs` (документаційні коментарі для всіх публічних
оголошень), `prefer_final_locals`, `directives_ordering` та ін.
